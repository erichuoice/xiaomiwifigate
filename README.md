# wifi-gate · 答对中小学题目才放行上网

路由器侧把设备「暂停联网」，设备仍然连着 Wi-Fi、能打开局域网里的本程序；
孩子在这里**逐题作答**，全部答对后，程序调用小米路由器的局域网接口把该设备放行。

界面与流程参考了开源项目 [StudyOnTV / 题了个题](https://github.com/chadyi/StudyOnTV)：
一题一屏、答完立刻显示对错和解析、整轮全对才算通过。

- **多套题库**：每套题库绑定一组设备，姐姐答小学题、弟弟答低年级题，互不干扰
- **题数换时长**：一套题库里可设多档「答对 N 题 → 换 M 分钟」，孩子自己选目标
- 零第三方依赖，只用 Python 3 标准库
- 内置 134 道（小学 + 初中，语文/数学/英语/科学/物理/化学/生物/历史/地理）
- 题库支持 CSV / TSV / JSON 导入，Excel 填表即可
- 手机、平板、电脑浏览器都能用，断网也能打开

## 一、先确认的前提（已实测，不是推测）

| 事项 | 结论 | 依据 |
|---|---|---|
| 「暂停联网」后还能打开局域网页面吗 | **能** | 小米的 `forbidWan` 语义是仅拦外网；局域网互访走二层交换，不经过 WAN 过滤 |
| 手机没有 SIM 卡会不会自动切蜂窝 | **不会**，这正是本方案最稳的形态 | 无蜂窝网络时设备只能留在 Wi-Fi |
| BE7000 后台能不能自动登录 | **能，明文即可** | `POST /cgi-bin/luci/api/xqsystem/login`，`username=admin&password=<明文>&logtype=2` → `{"code":0,"token":"<stok>"}` |
| 设备列表接口 | `GET /cgi-bin/luci/;stok=<stok>/api/misystem/devicelist` | 实测返回 27 台设备，含 `mac`、`ip[].ip`、`authority.wan` |
| 放行/阻断接口 | `GET .../api/xqsystem/set_mac_filter?mac=<MAC>&wan=0|1` | 社区抓包 + 本机链路验证 |
| `wan=0` 是「只断外网」还是「踢下线」 | **尚未实测** | 上线前必须做第六节的断网实测 |

> 这是路由器后台的内部接口，不是官方 API。`stok` 会过期，程序已实现
> 「返回 401/403 时用管理密码自动重登并重试一次」。

## 二、本机（当成 NAS）跑起来

> **也可以直接跑在小米路由器 BE7000 本机上。** 官方固件自带 Docker（数据放 USB 外接盘），
> 不需要刷机、不需要开 SSH，步骤见 [DEPLOY-ROUTER.md](DEPLOY-ROUTER.md)。
> 两条路用的是同一份代码，只是换个地方运行，`config.json` 和 `state/` 可以直接搬。

**首次启动不用准备 `config.json`**：程序发现没有配置会自动进入引导模式，
打开浏览器访问就会跳到 `/setup`，在那里填路由器管理密码，它自己生成配置文件。

```bash
cd wifi-gate
python3 server.py
```

| 用途 | 地址 |
|---|---|
| 答题页（手机 / iPad） | `http://<内网IP>:8080/` |
| 管理后台 | `http://<内网IP>:8080/admin` |

> **端口冲突时**：默认 8080。若宿主该端口已被占用（小米路由器 BE7000 实测如此，
> 会报 `Address in use`），启动时加 `-e WIFIGATE_PORT=8088` 即可，优先级高于配置文件，
> 引导模式下也生效。

**首次启动会进入引导模式**：此时访问以上任何地址都会跳到 `/setup`，在那里填
路由器管理密码即可——**答题后台的登录密码默认与它相同，只需要填一次**。
保存后自动生成 `config.json`（权限 600），立即生效、无需重启。

首次启动还会按学段把内置题库拆成「小学题库」「初中题库」两套，各带
`3 题→30 分钟` / `5 题→60 分钟` 两档，设备归属为空——去后台「设备」页分配即可。

想先看设备侧的完整流程，不必真拿手机：

```bash
# 只打印口径：属于哪套题库、有哪些档位、还剩多少分钟
python3 simulate_device.py --url http://<内网IP>:8080

# 选第 2 档并全部答对，走完放行（档位从 0 开始）
python3 simulate_device.py --url http://<内网IP>:8080 \
        --password 管理密码 --mode correct --tier 1

# 故意答错，看「整轮重来 + 错误次数累积 + 锁定」
python3 simulate_device.py --url http://<内网IP>:8080 \
        --password 管理密码 --mode wrong --rounds 3
```

自检 189 项：

```bash
python3 selftest.py
```

## 三、Docker 常驻

```bash
chmod +x gate.sh
./gate.sh check        # 部署前检查
./gate.sh up           # 构建并常驻启动
```

**必须 `network_mode: host`。** bridge 模式下服务端看到的客户端全是
`172.17.0.1`，ARP 表里也只有 Docker 网关，答对题会放行错设备。
host 模式下不写 `ports:`，端口由 `config.json` 决定。

| 命令 | 作用 |
|---|---|
| `./gate.sh up` / `down` / `restart` | 启停 |
| `./gate.sh status` / `logs` | 状态、健康检查、跟随日志 |
| `./gate.sh check` | 配置与权限检查 |
| `./gate.sh selftest` | 容器内 189 项全链路自检 |
| `./gate.sh sim --mode correct --password xxx --tier 1` | 容器内模拟手机答题 |
| `./gate.sh probe` | 只读探测路由器（不改规则） |
| `./gate.sh dryrun` / `live` | 切换演练 / 真实放行 |
| `./gate.sh restore` | 应急：把记录过的设备全部放行 |

镜像里不含 `config.json`（`.dockerignore` 排除），管理密码不会进镜像层。
容器以 root 启动后由 `docker-entrypoint.py` 把配置复制成 `/tmp` 的 600 副本、
修正 `state` 属主，再降权到 `PUID/PGID` 运行；收到 `SIGTERM` 优雅退出。

### 3.1 更新程序（后台一键 / 自动）

后台「设置 → 程序更新」里可以做三件事：

| 操作 | 说明 |
|---|---|
| 检查更新 | 读远端 `VERSION` 与本地比对，显示「有新版本 / 已是最新」 |
| 立即更新并重启 | 下载 GitHub 上的主干代码，覆盖程序文件，2 秒后进程自重启 |
| 每 6 小时自动检查 / 自动安装 | 前者只提示，后者发现新版本直接更新并重启 |

安全边界：**只覆盖程序文件**，`config.json`、`state/`（题库、授权记录、日志）永不触碰；
替换前会把即将被覆盖的文件打包到 `state/backup/<旧版本>-<时间>.tar.gz`（保留最近 5 份），
要回退就把里面的东西解回程序目录再重启。

路由器不能直连 GitHub 时，下载会走加速站（默认 `https://gh-proxy.com/`，失败再直连）。
要换源用环境变量：

```bash
-e WIFIGATE_MIRROR=https://gh-proxy.com/,direct
```

`direct` 表示直连；也可以写自己的反代地址。自动安装会把正在答题的人打断约 2–3 秒，
不想被打断就只开「自动检查」，看到提示再手动点更新。

> 前提：程序目录对进程可写。路由器那种「U 盘目录挂进容器」的部署最合适，
> 更新直接落到 U 盘，重启容器也在。若直接用官方镜像跑内置代码（没有挂载），
> 更新只改容器可写层，`docker rm` 重建后会退回镜像里的旧版本 —— 这种部署请继续用镜像升级。

发版约定：**改完代码要同时改 `VERSION`**（如 `3.1.0` → `3.1.1`）再推，否则只改了内容、
版本号没动，各处的「检查更新」不会认为有新版本（安装本身仍然可用）。

## 四、多题库与时间档位

### 4.1 三个概念

```
题库（bank）  一套题目 + 一组奖励档位 + 一组受控设备
档位（tier）  答对 N 道题 → 换 M 分钟上网时间（M = 0 表示一直放行）
设备归属      每台受控设备只属于一个题库；没归属的设备一律不受控
```

例：姐姐的 iPad 归「小学题库」，档位 `3 题→30 分 / 5 题→60 分`；
弟弟的平板归「一年级题库」，档位 `2 题→20 分 / 4 题→45 分`。
两台设备各答各的题，互不影响。

### 4.2 后台怎么配

| 页面 | 能做什么 |
|---|---|
| 题库 | 顶部下拉切换/新建/删除题库；改名称；增删档位；增删改题目；导出本题库 CSV |
| 导入 | 选目标题库，粘贴或选文件导入（追加 / 覆盖），下载模板，整份备份与恢复 |
| 设备 | 每台设备一个下拉：选题库或「不受控」，改完立即生效 |
| 设置 | 每人每天累计上限（0 = 不限）、答题页底部提示语、一键清除答题锁定 |

保存即生效，不用重启容器：可变配置写在 `state/runtime.json`（原子写、持久化）；
`config.json` 只在引导页保存那一次被写入，之后运行期只读。

### 4.3 内置题库

`question_bank.json`，134 道：

| 学段 | 科目 | 题数 |
|---|---|---|
| 小学 | 语文 / 数学 / 英语 / 科学 | 16 / 22 / 15 / 10 |
| 初中 | 语文 / 数学 / 英语 / 物理 / 化学 / 生物 / 历史 / 地理 | 10 / 15 / 10 / 10 / 8 / 8 / 5 / 5 |

每题字段：

| 字段 | 说明 |
|---|---|
| `type` | `single` 单选 / `multi` 多选 / `judge` 判断 |
| `stage` `grade` `subject` | 学段、年级、科目（答题页会显示） |
| `text` `options` | 题干与选项（2-8 个） |
| `answer` | 单选题为序号（**从 0 开始**），多选题为序号数组 |
| `explain` | 解析，答完题展示给孩子 |
| `star` | 难度 1-5，答题页显示星级 |

题库名含「小学」或「初中」时，「用内置题库覆盖」只灌对应学段。
**答案只存在服务端，答题页拿不到。**

### 4.4 导入（Excel / CSV / JSON）

后台「导入」页 → 选目标题库 → 下载模板 CSV → 用 Excel 填好另存为 CSV →
选文件或直接粘贴 → 先预览 → 开始导入。

| 列 | 是否必填 | 说明 |
|---|---|---|
| 题型 | 否 | 单选 / 多选 / 判断，留空按单选 |
| 学段 / 年级 / 科目 | 否 | 小学 / 初中；三年级；数学… |
| 题干 | **是** | |
| 选项A ~ 选项D（可到 H） | **是** | 判断题为「正确 / 错误」，不填则自动补 |
| 答案 | **是** | `B`、`a`、`A,C`、`AC`、`1,3`、`对`/`错`、`√`/`×` 都认 |
| 解析 | 否 | 建议写，孩子答完能看到 |
| 难度 | 否 | 1-5，默认 2 |

细节：

- 列顺序随意，表头用中英文别名都能识别（题干/题目/question、科目/学科/subject…）
- 分隔符自动判定（逗号、制表符、分号），Excel 导出的 CSV 直接可用
- **无表头也能导入**：按「题干 | 选项A~D | 答案 | 解析」的位置解析
- 逐行校验：某一行出错不影响其它行，后台会列出「第 N 行：原因」
- 两种模式：**追加**（按题干去重）/ **覆盖**；都只作用于所选题库

### 4.5 导出与备份

| 入口 | 内容 |
|---|---|
| 导出 CSV | 当前题库，可直接用 Excel 打开继续编辑 |
| 导出备份 JSON | **全部题库 + 档位 + 设备归属 + 设置**，换 NAS 时整份恢复 |
| 导入备份 | 选 JSON 文件即可还原；旧版单题库备份也能读 |

## 五、答题与放行逻辑

```
手机连 Wi-Fi（已被管理员「暂停联网」）
        ↓ 打开 http://NAS_IP:8080/
GET  /api/quiz      ← 返回本机所属题库、可选档位、剩余分钟（不发题）
        ↓ 孩子点「答 3 题 · 30 分钟」
POST /api/start     ← 按该档位抽 3 道题，只下发题干和选项
POST /api/answer    ← 逐题提交，返回对错 + 正确答案 + 解析 + 下一题
        ↓ 一轮全部答对
调用 set_mac_filter?mac=…&wan=1  → 放行，时长 = 所选档位
        ↓ 配额用完
调用 set_mac_filter?mac=…&wan=0  → 重新断开，需再答一次
```

| 规则 | 行为 |
|---|---|
| 答错一题 | 立刻显示正确答案与解析，继续下一题；本轮不算通过 |
| 一轮有错 | 整轮重来（同一档位重新抽题），错误次数 +1 |
| 连错 3 轮 | 锁定 60 秒（`server.max_wrong_per_window` / `lock_seconds`） |
| 时长重新计时 | 还有剩余时再答，按本次档位**从现在重新算**，不叠加到原到期时间（所以选短档会把剩余时间改短） |
| 档位填 0 分钟 | 答对后永久放行，不再自动断网 |
| 到期倒计时 | 答对后的结果页显示「还剩 12:34 自动断网」，每秒递减（以服务端时间为准，手机时钟不准也不影响）；到 0 秒后服务端 `reblock_worker` 最长 20 秒内把设备重新断开，页面自动刷新回「已断网」状态 |
| 每日上限 | 设置里可限「每人每天最多获得 N 分钟」，超出部分按剩余额度发放，用完提示明天再来 |
| 中途刷新 | 服务端保持进度 30 分钟，回来接着答 |
| 未归属设备 | 直接提示「这台设备不用答题」，**不调用路由器接口** |
| 代答 | 任何设备打开答题页，都能从「为哪台设备解锁」里选一台受控设备来答题，**谁做题、放行谁是分开的** |

### 5.1 代答（任一设备替另一台答题）

场景：孩子的平板被暂停联网，但他手上没有能用的设备；或者家长想用自己的手机
替平板答题解锁。

页面顶部会列出所有受控设备（名字取自小米后台，如 `Huo-2`），选中哪台，
答对后就放行哪台。实现上：

```
GET  /api/quiz   → targets: [{mac, name, bank, tiers, remaining_minutes, is_self}]
POST /api/start  → {tier: 0, target: "<目标设备 MAC>"}
                   target 缺省时是本机（原有行为不变）
```

服务端只接受**受控清单里**的 MAC，其它值返回 403 `not_managed`。
注意这意味着**同一局域网内任何设备都能替受控设备答题**——符合“家里谁有空谁
去答”的用法；若不希望这样，把该设备从受控清单里移出即可。

**程序没有任何「主动拉黑」的路径**：初始断网由管理员在小米 WiFi App 里手动点
「暂停联网」，程序只负责放行与到期回收，避免误伤摄像头、音箱、网关这些 IoT 设备。
（`3.2.0` 起例外：`gatectl.py` 可以对**受控清单里的设备**手动断网/放行，
非受控设备一律拒绝，不影响 IoT。）

### 5.2 手动断网/放行（家长控制）

**后台直接操作**（3.3.0 起）：打开 `/admin` → **设备** 页 → **每台设备**右侧都有
「断网 / 放行」按钮（不要求先分配题库，列表里的手机、平板、音箱都能直接控制）：
断网立即生效；放行在弹框里填分钟数（留空或 0 = 永久放行），到期自动断。
操作完列表自动刷新外网状态。手动控制是家长意志，不影响设备的题库归属，
未分配题库的设备也不会因此被「自动」断网或回收。

**设备名旁的倒计时**（3.4.0 起）：只要设备处于**暂时放行**（手动放行填了分钟数，
或答题解锁），设备名旁边就显示「剩 12:34」实时倒计时，每秒递减，最后一分钟变红；
以服务端时间校准，手机时钟不准也不影响。到点显示「已到期」并自动刷新设备列表。
永久放行、已断网的设备不显示倒计时。

（`3.3.1` 起健壮性修复：路由器登录态（stok）失效时自动重登重试，不再误报
「路由器设备列表里没有这台设备」；真拉不到设备列表时如实提示「暂时拉取失败，
请刷新再试」，与「MAC 不存在」区分开。`3.3.3` 修复后台按钮把 options 误当
data 传给 `api()` 导致请求体缺少 MAC 的问题，另加前端调用约定自检。）

**命令行方式**（配合路由器 SSH 通道，见 DEPLOY-ROUTER.md）：

```sh
python3 gatectl.py list          # 所有受控设备的状态、剩余、今日累计
python3 gatectl.py off huo-2     # 立即断网（它答一轮题即可恢复）
python3 gatectl.py on  huo-2 30  # 放行 30 分钟，到点自动断
python3 gatectl.py on  huo-2     # 放行，不给分钟数 = 永久
```

两种方式走同一套接口（`/api/admin/device/wan`），规则相同：
手动放行是家长意志，**不受每日上限约束**，也不计入「今日累计」；
可对**设备列表里的任何设备**手动操作（不要求已分配题库），但 MAC 必须真实
存在，防止手滑；未分配题库的设备只受手动控制，不会被自动断网或回收。
命令行的 `<设备>` 支持名称模糊匹配（不分大小写）与 MAC 前缀匹配。

### 5.3 设备答题时段（周一～周日分别设置，3.5.0 起）

给**每台设备**单独设定「什么时间可以靠答题放行上网」，其余时间不能答题、设备保持断网。
打开 `/admin` → **设备** 页 → 设备名下方的「**时段设置**」。

| 能力 | 说明 |
|---|---|
| 按周设置 | 周一～周日各一行，互不影响 |
| 多个时段 | 同一天可填多段，用逗号隔开，如 `07:30-08:00, 18:00-20:00` |
| 跨夜时段 | 支持 `22:00-06:00`（结束小于开始即视为跨午夜） |
| 全天 | `00:00-24:00` |
| 某天不开放 | 该行留空 |
| 不限制 | 整周留空，或不勾选「启用时段限制」 |
| 快捷填入 | 输入一个时段后点「每天 / 工作日 / 周末 / 清空」 |

**规则怎么生效**

| 时刻 | 行为 |
|---|---|
| 允许时段内 | 正常答题；答对放行，但**到期时间最多到本时段结束**，不会跨进禁止时段 |
| 禁止时段 | 不能开始答题，答题页显示「现在不是答题时间」及下次开放时间；已有放行自动断网 |
| 时段边界 | 后台设备页与答题页按服务端时间自动刷新，孩子开着页面等到点就能答 |
| 家长手动「放行」 | **临时破例，不受时段限制**（应急用），也不会被时段自动回收 |

几个边界：

- 规则只管「答题解锁」这条路径；设备要形成闭环，仍需先在小米 WiFi App 里初始断网（见第六节）。
- 时段外**只回收本系统发放过的放行**（有放行记录、且不是家长手动放行）；没有放行记录的设备不会被主动改动，避免误伤。
- 时间按**服务所在时区**解释（容器已设 `TZ=Asia/Shanghai`，即北京时间）。
- 若答题过程中刚好跨过时段结束，页面提示「答案对了，但已过答题时间」，不会放行。
- 规则存在 `state/runtime.json` 的 `schedules` 里，随备份一起导出；导入旧版备份不会清掉现有规则。
- 新增接口：`GET /api/admin/schedules`（规则 + 当前状态 + 状态翻转时刻）、
  `POST /api/admin/schedule`（`{"mac":..., "schedule": {...}}`，`schedule: null` 为删除）。

### 5.4 AI 智能题库与学情（3.6.0 起）

后台新增 **「AI 出题」** 和 **「学情」** 两个页签，对应 6 件事：

| 需求 | 落地方式 |
|---|---|
| AI 随机生成题目 | 调用 OpenAI 兼容 `/chat/completions`，预设 DeepSeek / 阿里百炼；生成后过题目格式校验、按题干去重，预览勾选后入库 |
| 单选 / 判断 / 多选 | 每次生成自动按 50% 单选 / 25% 多选 / 25% 判断分配，也可手动填三种题量；判断题选项固定「正确 / 错误」 |
| 保留错题、适时再出类似题 | `state/learning.json` 按设备存错题（题干、知识点、错误次数、复习到期）；按 2 小时 → 1 天 → 3 天 → 7 天 → 15 天间隔复习，到期时插入原题或**同知识点的其它题**（避免死记答案） |
| 判断知识能力、针对弱项多出题 | 按知识点记录正确率与 EWMA 掌握度（至少答 2 次才下结论），掌握度 < 0.62 判为弱项；组卷时弱项加权最多 3 倍，但**同一知识点一轮最多占一半**，并尽量让三种题型都出现 |
| 贴合广东广州学生 | 命题人设、广州本地情境（珠江、广州塔、陈家祠、白云山、早茶点心、荔枝、醒狮、南沙湿地等）、简体中文与课标约束写进 prompt；英语科目题干可用英文 |
| 按当前学习进度出题 | 按广州校历推断学年 / 学期 / 教学周与已学范围（如 11 月 = 第一学期约第 11 教学周、期中前后），作为**最高优先级**写进 prompt；教材版本可选；进度与孩子实际不符时可在后台手动指定单元范围 |

**在哪里填 API Key（重要）**

打开 `/admin` → **AI 出题** → ①「连接 AI」→ **API Key 密码框** → 填 DeepSeek 的 `sk-…` → 点「保存连接设置」，再点「测试连接」。

| 安全措施 | 说明 |
|---|---|
| 存储位置 | 只写路由器 `state/ai.json`，文件权限 600，`state/` 已在 `.gitignore` 排除 |
| 回显 | 后台只显示 `sk-****后四位`，输入框永不回填明文；接口响应里没有 `api_key` 字段 |
| 不外泄 | 不进日志、不进备份导出、不进 GitHub；「清除 Key」可随时删除 |
| 降级 | 没填 Key 或接口失败时自动用离线模板出题（带广州情境、三种题型），功能不会中断 |

**教学进度**默认按当前日期自动推断，并在页首显示「学年 / 学期 / 教学周 / 命题范围」；
这是按校历的粗略估算，若与学校实际进度不符，把「进度方式」改成「手动指定范围」并填
`第 1—3 单元（分数加减）` 之类即可，手动值优先。

**学情页**能看到每台设备的正确率、答题轮次、错题数、待复习数、弱项 TOP、错题清单，
并可单独清空某台设备的学情（不影响题库和已发放的上网时间）。
答题页也会显示每题知识点，以及本轮的「重点练习」提示。

新增接口：`GET/POST /api/admin/ai/config`、`POST /api/admin/ai/test`、
`POST /api/admin/ai/generate`（只生成预览，不入库）、`POST /api/admin/ai/apply`（勾选题入库）、
`GET /api/admin/learning`、`POST /api/admin/learning/clear`。

（`3.6.1` 修复：「预览并入库」的题目正文被题库列表的折叠样式 `.qbody{display:none}`
误伤，只剩勾选框看不到题。折叠样式现限定在题库卡片内，预览正文强制可见，

### 5.5 定时自动出题（无人值守，3.7.0 起）

「AI 出题」页的「出一批新题」原本要人工点三次（生成预览 → 勾选 → 入库）。
后台新增 **自动出题** 页签，开启后由路由器上的服务自己按时完成整条链路，
**不需要任何人操作，也不依赖电脑、手机或外部调度在线**。

| 项目 | 说明 |
|---|---|
| 触发 | 服务内守护线程每 30 秒检查一次；每天固定时刻（默认广州时间 03:00）或每隔 N 小时。**升级后默认已启用** |
| 做什么 | 生成 → 格式校验 → 按题干去重 → 直接追加进指定题库 → 按上限淘汰最旧的自动题 → 写一条运行记录 |
| 命题依据 | 学段 / 年级 / 科目 / 知识点 / 题型配比、广州本地化、教材版本与当前教学进度（沿用 5.4 的 AI 配置） |
| API Key | 已配 Key 走 DeepSeek；未配或接口失败自动降级离线模板；也可强制「只用离线」 |
| 弱项 | 可指定一台设备，按它的错题与弱项知识点出题 |
| 去重 | 生成时避开题库已有题干，入库时再按题干去重，重复题不会进题库 |
| 上限 | 「最多保留自动题」默认 60 道，超出只删最旧的自动题；内置题和手动入库的题一律不动 |
| 停机 | 不补跑。服务恢复后按当前时间排下一次，不会一次补几十轮 |
| 失败 | 记一条失败记录并照常推进下次时间，不重试轰炸；答题 / 放行主流程完全不受影响 |
| 存储 | 只写 `state/auto_bank.json`（权限 600），不进 GitHub、不进题库导入导出 |

**升级后默认已启用**：每天广州时间 03:00 出 10 道新题、直接追加到第一个题库、
最多保留 60 道自动题，全程无需人工操作，也不消耗外部调度。配了 DeepSeek Key 就走 AI，
没配或接口失败自动用离线模板。状态卡会显示下次执行时间与已入库的自动题数量。

要改时间 / 题量 / 题库，或干脆关掉，去 `/admin` →「自动出题」：

1. 开关「启用定时自动出题」，选每天固定时间或每隔 N 小时（建议设在凌晨）。
2. 填题量、目标题库、学段 / 年级 / 科目、出题方式；可点「用 AI 出题 ③ 当前参数填入」一键同步。
3. 点「保存自动出题设置」。状态卡会显示下次执行时间、目标题库题数、自动题数量与 Key 状态。
4. 不确定效果就点「立即试跑一次」：先保存当前设置，再完整跑一遍并直接入库；
   「最近运行记录」里能看到生成数、入库数、跳过数、淘汰数、耗时与失败原因。

只改题量或科目**不会重置计时**，只有开关 / 频率 / 时刻真的变了才重排下次执行时间。
新增接口：`GET/POST /api/admin/auto-bank`、`POST /api/admin/auto-bank/run`、
`POST /api/admin/auto-bank/clear`。

## 六、上线前必须做的一步

1. 手机连**主 Wi-Fi**（不是访客），关掉移动数据。
2. 打开 `http://<NAS内网IP>:8080/`，确认能看到题库和档位。
3. 小米 WiFi App → 设备列表 → 选中这台手机 → **暂停联网**（别点「加入黑名单」）。
4. 再刷新一次页面：
   - **还能打开** → 方案成立，继续第 5 步；
   - 打不开 → 说明这台路由器是「踢下线」语义，需要换管控方式（见排错表）。
5. 在后台「设备」页刷新，确认该手机 `authority.wan` 变成 `0`；答对题后再刷新，变回 `1`。
6. 确认无误后关闭演练：

```bash
./gate.sh live      # 或手动把 config.json 的 "dry_run" 改成 false 后重启
```

当前出厂配置是 `mode=miwifi` + `dry_run=true`：**会真的登录路由器、真的解析 MAC，
但不发出修改规则的请求**，所以在你完成第 1-5 步之前，它不会动你家任何设备。

## 八、排错

| 现象 | 原因与处理 |
|---|---|
| 断网后页面打不开 | 用的是「加入黑名单」而不是「暂停联网」；或手机连的是访客 Wi-Fi；或 NAS 与手机不在同一网段 |
| 页面提示「这台设备不用答题」 | 该设备还没分配题库。后台「设备」页选一套题库即可 |
| 答对了却提示放行失败 | 看 `state/access.log` 里的 `ALLOW-FAIL`；多是路由器密码变更导致 `stok` 失效，`./gate.sh restart` 后重试；也可先 `./gate.sh probe --check-ip <手机IP>` |
| 后台看不到设备 | `router.mode` 还是 `mock`；或容器不是 host 网络 |
| 保存题库报「第 1 档要求 N 道题」 | 档位题数大于该题库的题目数，先补题或改小档位 |
| `authority.wan` 一直是 1 | 该设备不在路由器的管控范围，检查小米 App 里的「暂停联网」是否真的生效 |
| 答对后放行了错误设备 | 一定是容器跑在 bridge 网络，改成 `network_mode: host` |
| 被锁定了 | 等 60 秒；或后台「设置 → 清除所有答题锁定」立即解锁；重启容器也会清空（内存态计数） |

## 九、安全提醒

- `config.json` 内含路由器管理密码，权限保持 600，**不要提交到公开仓库**。
- 后台管理密码同样在 `config.json`，改完需重启容器。
- 小米后台登录走局域网 HTTP 明文，这是其自身行为，别把本服务暴露到公网。
- 本服务只应监听局域网；如需外网访问，请自行加反向代理与鉴权，并把
  `server.trust_x_forwarded_for` 打开后仅由代理注入 XFF。
